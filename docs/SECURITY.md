# 보안·신뢰성 설계 (SECURITY)

KS-Fix가 다루는 표준안은 미발간 초안일 수 있으므로 **문서가 밖으로 나가지 않고, 원본과 기술적 내용이 바뀌지 않는 것**을 가장 먼저 지킵니다.

## 1. 데이터 흐름과 외부 전송

| 실행 형태 | 문서가 가는 곳 | 외부 전송 |
|---|---|---|
| CLI·Windows 실행파일·Docker(LLM 끔, 기본) | 이 컴퓨터의 메모리·임시 폴더 | 없음 |
| 로컬 웹서버 | 127.0.0.1의 KS-Fix 서버 → 작업별 임시 폴더(1시간 뒤 삭제) | 없음 |
| 브라우저 데모 | 브라우저 메모리(Web Worker) | 없음(처리 엔진 파일만 내려받음) |
| 로컬 LLM(Ollama 등, localhost) | 판정 대상 문장만 로컬 LLM 서버로 | 없음 |
| 외부 LLM 프로필 | 판정 대상 문장이 외부 API로 | **있음** — 화면·명령줄·리포트에 경고 표시 |

- LLM에는 문서 전체가 아니라 ‘할 수 있다’·‘반드시’ 후보 문장(또는 저신뢰 문단)만 보냅니다.
- `base_url`이 localhost·127.0.0.1·host.docker.internal이 아니면 자동으로 외부로 분류합니다.
- 실제 KS 문서·미발간 초안은 외부 API로 보내지 않는 것을 원칙으로 합니다(개발 중에도 실제 문서는 로컬에서만 썼고 저장소에 넣지 않았습니다).

## 2. 원본 보호와 기술적 내용 불변

| ID | 보장 | 방법 |
|---|---|---|
| INV-01 | 수치·단위·표준번호·표 셀 값 불변 | 편집 전 문단별 사전 점검(바뀌는 편집은 메모로 강등) + 편집 후 결과 문서를 다시 읽어 문서 전체 토큰 비교. 다르면 **모든 편집을 철회**하고 메모만 남긴 문서를 냅니다 |
| INV-02 | 입력 파일 불변 | 코어는 bytes만 받고 새 bytes를 돌려줌. CLI는 처리 전후 SHA-256 비교, 출력 경로가 입력과 같으면 거부 |
| INV-03 | 출력 docx 무결성 | 다시 열기, 모든 XML 파싱, 변경추적·메모 ID 중복/충돌, 메모 범위 짝, 참조 메모 존재 확인 |

자동 수정하지 않는 곳(메모로만): 필드 코드·필드 결과(목차·상호참조), 수식(OMML), 그림·텍스트 상자, 기존 변경추적 안, 하이퍼링크 경계를 넘는 구간. 기존 메모와 변경추적은 보존합니다. 기존 변경추적이 있는 문서는 기본으로 새 수정을 메모로만 남깁니다.

## 3. 입력 검증(`src/ksfix/io/safety.py`)

| 위협 | 대응 |
|---|---|
| 큰 파일·메모리 고갈 | 업로드 30 MB 한도(Content-Length와 실제 읽은 양 모두 검사) |
| 압축 폭탄 | 내부 파일 5,000개, 압축 해제 합계 400 MB, 큰 항목 압축 비율 250배 상한 |
| XXE(외부 엔터티) | DTD·ENTITY 선언이 있는 XML 부분은 거부. XML 파서는 엔터티를 풀지 않음(python-docx/lxml 설정) |
| 매크로 | `vbaProject.bin`·macroEnabled 콘텐츠 형식(.docm) 거부 |
| 암호화·구형 문서 | OLE 형식(.doc·암호화 docx)과 암호화 zip 항목은 안내 메시지와 함께 거부 |
| 손상 파일 | zip 무결성 검사 후 한국어 오류 메시지(종료 코드 2·HTTP 400) |

## 4. 웹서버(`src/ksfix/web/app.py`)

- 기본 바인딩 **127.0.0.1**(다른 컴퓨터에서 접속 불가). Docker도 `127.0.0.1:8765`에만 노출합니다. 업무망 서버로 공유하려면 방화벽·접근통제를 갖춘 뒤 바꿉니다.
- 작업 ID는 무작위 32자리 16진수, 내려받기는 정해진 파일 키만 허용(경로 조작 차단), 작업 폴더는 1시간 뒤 삭제(`KSFIX_JOB_TTL`).
- 문서 내용·파일명은 로그에 남기지 않습니다(작업 ID·크기·모드·처리 시간만).
- 보안 헤더: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, 웹 UI에는 `Content-Security-Policy`(자기 출처의 스크립트·스타일만, 인라인 스크립트 금지).
- 웹 UI는 문서 텍스트를 모두 `textContent`로 넣고(HTML로 해석하지 않음), 리포트 HTML은 Jinja2 자동 이스케이프를 씁니다. CDN·외부 글꼴을 쓰지 않습니다.
- Docker: 비루트 사용자(uid 10001), 읽기 전용 파일시스템 + `/tmp`만 tmpfs, 헬스체크.

## 5. 비밀값

- API 키는 프로필 파일에 쓰지 않고 `api_key_env`로 환경변수 이름만 적습니다. 값은 `.env`(커밋 금지, `.gitignore`) 또는 환경변수에 둡니다.
- `scripts/check.py`가 커밋 전 검사에서 추적 중인 파일의 비밀값 패턴과 `local_samples/` 포함 여부를 확인합니다.
- LLM 응답 캐시(`.ksfix_cache/`)에는 판정 대상 문장이 들어가므로 커밋하지 않으며(`.gitignore`) 필요하면 지웁니다.

## 6. 공급망·라이선스

- 실행 의존성은 python-docx·lxml·PyYAML·Jinja2(코어)와 FastAPI·uvicorn·python-multipart(웹)뿐이며 모두 허용형 라이선스입니다. LLM 호출은 표준 라이브러리(urllib)만 씁니다. 목록: [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)
- CI는 GitHub 공식 액션만 쓰고, 릴리스 파일은 기본 `GITHUB_TOKEN`으로 올립니다.
- 브라우저 데모는 Pyodide 0.27.2를 버전을 고정해 내려받습니다.

## 7. 알려진 한계

- Windows 실행파일은 코드 서명이 없습니다(배포 기관 인증서로 서명 권장).
- 웹서버에는 사용자 인증이 없습니다. 127.0.0.1 밖으로 공개할 때는 앞단에 인증·TLS를 두어야 합니다.
- LLM 판정은 확률적이며 오판할 수 있습니다. AI 제안은 변경추적으로만 반영되고 사람이 수락해야 확정됩니다.

## 8. 취약점 신고

보안 문제를 발견하면 공개 이슈 대신 저장소 관리자에게 비공개로 알려 주십시오(재현 방법, 영향, 가능하면 합성 문서 예시). 실제 KS 문서는 첨부하지 마십시오.
