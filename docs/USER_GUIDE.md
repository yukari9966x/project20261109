# 사용자 안내서 (USER_GUIDE)

KS-Fix로 표준안(.docx)을 점검하고 교정하는 방법입니다. 설치는 [README](../README.md#빠른-실행-windows-실행파일--pip--docker)를 봅니다.

## 1. 무엇을 해 주나

| 하는 일 | 결과 |
|---|---|
| 문서 구조 인식 | 문단마다 역할(머리말·적용범위·용어·표 제목·부속서 등)과 소속 절을 정합니다 |
| 점검 | KS A 0001:2023 규칙으로 위반을 찾고, 지적마다 근거 조항·위치·수정안을 냅니다 |
| 교정 | 확정할 수 있는 항목은 Word 변경추적으로 고치고 메모에 근거를 답니다 |
| 리포트 | 요약, 지적 목록, 부속서 A 검토 항목 53개 체크리스트, 교정 전후 통과율 |

모든 자동 수정은 **변경추적**으로 남으므로, 최종 결정은 담당자가 Word에서 수락·거절로 합니다.

## 2. 웹 화면에서 쓰기

1. 서버를 켭니다: Windows 실행파일은 `ksfix.exe` 실행, pip 설치는 `ksfix serve --open`, Docker는 `docker compose up`. 브라우저에서 http://127.0.0.1:8765 가 열립니다.
2. **① 문서 올리기** — .docx 파일을 끌어 놓거나 눌러서 고릅니다(최대 30 MB).
3. **② 출력 선택**
   - 출력: **변경추적본**(기본, 수정 + 근거 메모) / **반영본**(수정을 모두 반영, 판단이 필요한 항목은 메모) / **점검만**(문서는 만들지 않고 리포트만)
   - 규칙 범위: 구현된 규칙 전체(기본) / P0(핵심) / P0 + P0b
   - AI(LLM): 끔(기본) 또는 설정한 프로필. 외부 API 프로필을 고르면 문서 문장이 외부로 전송된다는 경고가 나옵니다.
4. **점검·교정 시작** 단추를 누르면 몇 초 안에 결과가 나옵니다.
5. **③ 결과 확인·내려받기**
   - 요약 카드: 지적 수(오류·경고·참고), 자동수정 수, 교정 전후 규칙 통과율, 불변성 검증 결과
   - 지적 목록: 심각도·분류·상태·검색어로 거를 수 있고, 행마다 근거 조항과 조치(자동수정·제안·검토 필요·판단 필요)가 보입니다.
   - 부속서 A 체크리스트: 항목별 자동 판정(통과·위반) 또는 ‘사람 확인’ 표시
   - 내려받기: 변경추적본(또는 반영본) .docx, 리포트 HTML·JSON, 감사 로그(JSONL). 서버에 올린 파일과 결과는 1시간 뒤 자동으로 지워집니다.

## 3. 변경추적본을 Word에서 확인하기

1. 내려받은 `*.ksfix-tracked.docx`를 Word로 엽니다. “이 문서에는 다른 파일을 참조하는 필드가 있습니다. 업데이트하시겠습니까?”가 나오면 **예**를 누르면 목차가 갱신됩니다.
2. **검토** 탭에서 ‘모든 변경 내용’ 보기로 두면 삭제는 취소선, 삽입은 밑줄로 보입니다. 변경한 사람은 `KS-Fix`입니다.
3. 메모는 `[규칙 ID · 근거 조항] 설명 (상태)` 꼴입니다. 예: `[QTY-01 · KS A 0001:2023 부속서 L, J.3] 수치와 단위기호 사이를 한 칸 띄웁니다('150kg' → '150 kg'). (자동수정)`. AI 제안은 상태 자리에 `(AI 제안 · 모델 이름 · 신뢰도 0.90)`처럼 모델과 신뢰도가 표시됩니다.
4. ‘다음’으로 하나씩 보며 **수락** 또는 **거절**합니다. 삽입을 거절해도 근거 메모는 남습니다.
5. 지적만 있고 수정이 없는 항목(검토 필요·판단 필요)은 메모만 달려 있으니 직접 고칩니다.

메모 상태 뜻

| 표시 | 뜻 |
|---|---|
| 자동수정 | 규칙으로 확정할 수 있어 변경추적으로 고친 항목 |
| 제안 | 고칠 문장을 제안했지만 자동으로 바꾸지 않은 항목(메모의 제안을 보고 결정) |
| AI 제안 | LLM이 판정·제안한 항목(변경추적본에서만 변경추적으로 반영, 반영본에서는 메모) |
| 검토 필요 | 위반이지만 고칠 방법이 문맥에 따라 달라 사람이 고쳐야 하는 항목 |
| 판단 필요 | 의미를 알아야 판단할 수 있는 항목(예: ‘할 수 있다’가 허용인지 가능성인지) |

## 4. 명령줄(CLI)

```bash
ksfix check 표준안.docx -o out
```
점검만 하고 리포트(HTML·JSON)를 만듭니다. `--fail-on error`를 주면 오류가 있을 때 종료 코드 1(자동화용).

```bash
ksfix fix 표준안.docx -o out --mode tracked
```
`--mode tracked`(변경추적본, 기본) · `clean`(반영본) · `report`(리포트만). 리포트·감사 로그를 함께 만듭니다.

```bash
ksfix inspect 표준안.docx
```
문단별 역할·자동번호·스타일을 표로 보여 줍니다(`--all`: 빈 문단·표 안 문단 포함, `--json`: JSON).

```bash
ksfix rules
```
규칙 목록(● 구현, ○ 미구현). `--markdown`은 [RULES.md](RULES.md) 형식으로 출력합니다.

공통 옵션

| 옵션 | 뜻 |
|---|---|
| `-o 디렉터리` | 출력 위치(기본 `out`). 입력 파일과 같은 경로에는 쓰지 않습니다 |
| `--rules P0,P0b` | 우선순위로 규칙 범위 지정. `--rules QTY-01,PUN-02`처럼 규칙 ID도 됩니다 |
| `--llm 프로필` | LLM 사용(기본 `none`). [LLM_SETUP.md](LLM_SETUP.md) 참고 |
| `--accept-existing-changes` | 기존 변경추적이 있는 문서도 자동 수정(기본은 메모만 — 남의 변경과 섞이지 않게) |

종료 코드: 0 정상 · 1 `--fail-on` 기준 이상의 지적 있음 · 2 입력 오류(손상·암호화·크기 초과 등) · 3 입력 파일 변경 감지 또는 출력 무결성 실패

## 5. 결과 파일

| 파일 | 내용 |
|---|---|
| `이름.ksfix-tracked.docx` | 변경추적본: 원문 + 변경추적 + 근거 메모. 기존 메모·변경추적은 그대로 둡니다 |
| `이름.ksfix-clean.docx` | 반영본: 자동 수정을 반영한 문서 + 판단이 필요한 항목의 메모 |
| `이름.ksfix-report.html` | 리포트(한 파일, 인터넷 없이 열림): 요약·구조·지적 목록·체크리스트·검증 결과 |
| `이름.ksfix-report.json` | 같은 내용의 JSON(다른 시스템 연계용) |
| `이름.ksfix-audit.jsonl` | 감사 로그: 편집마다 규칙 ID·문단·전후 텍스트·결정(적용·메모·철회)과 이유 |

결과 예시는 [examples/](../examples/)에 있습니다.

## 6. 브라우저 데모(설치 없음)

같은 화면을 Python 서버 없이 브라우저 안(Pyodide, Web Worker)에서 실행하는 판입니다. 문서는 브라우저 밖으로 나가지 않습니다. LLM 기능은 없습니다.

온라인 공개 주소는 두지 않았습니다(문서를 외부 서버에 올리지 않도록). 로컬에서 열려면(첫 실행 때 처리 엔진을 받으므로 인터넷 필요):

```bash
python scripts/build_pages.py
```
```bash
python -m http.server 8000 --directory site
```
그다음 http://127.0.0.1:8000 을 엽니다. 첫 실행 때 처리 엔진을 내려받아 수십 초가 걸리고, 그 뒤 처리는 1~2초입니다.

## 7. 자주 묻는 질문

- **.hwp·.doc 파일은?** Word나 한컴오피스에서 ‘다른 이름으로 저장 → Word 문서(.docx)’로 바꾼 뒤 올립니다.
- **지적이 틀린 것 같다면?** 변경추적에서 거절하면 됩니다. 반복되는 오탐은 규칙 ID와 문장 꼴을 알려 주시면 규칙과 테스트에 반영합니다.
- **수치가 바뀌지 않았는지 어떻게 아나?** 결과 문서를 다시 읽어 원본과 수치·단위·표준번호·표 값을 비교합니다. 다르면 모든 편집을 철회하고 리포트 ‘검증’에 표시합니다.
- **기존 메모·변경추적이 있는 문서는?** 그대로 보존합니다. 기존 변경추적이 있으면 기본으로 새 수정은 메모로만 남깁니다(`--accept-existing-changes`로 바꿀 수 있음).
- **목차가 바뀌지 않는다면?** Word에서 목차를 눌러 ‘필드 업데이트 → 전체 목차 업데이트’를 합니다.
